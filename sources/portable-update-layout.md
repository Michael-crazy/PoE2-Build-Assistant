# R02 便携 ZIP 更新：离线布局检查点

这是拟定布局的临时目录回归，不是已实现的更新器或 R01 便携包。只用 Python 标准库生成自编 ZIP、假程序字节、BD 占位文件和设置；不启动 EXE、PoB 或客户端，不下载、安装或发布。

```text
portable/
  program/             当前版本程序与引擎，可整体替换
  user/                独立持久数据，不包含在程序 ZIP 内
    builds/            BD 与导出文件
    settings/          助手与 PoB 设置
  staged-program/      ZIP 中 program/ 的预备副本
  previous-program/    换版前的程序副本
  rejected-program/    演练回退时移出的新版程序
```

此布局是后续 R01/R02 接线约束。尚未配置真实 PoB 的 BD/设置路径，也未迁移已有便携目录；必须先确认真实运行时所有持久写入都指向 `user/`。不能直接在现有 PoB 目录执行本演练步骤。

回归入口：`python3 -B -m unittest discover -s scripts -p 'test_portable_layout.py' -v`。
所有变更限定在测试自行创建的 `TemporaryDirectory`，结束自动清理；测试没有接受实际安装路径的接口。

- ZIP 只含 `program/`。测试模型先检查全部成员再读取并预备文件，用户目录成员及路径逃逸会被拒绝。
- 模拟程序已退出：`program` 移至 `previous-program`，预备目录移至 `program`。核对新版完整文件集，旧版独有文件不会残留。
- 对 `user/` 全部相对文件名和原始字节逐项比较，包含中文/空格文件名、二进制 BD 占位、两个设置文件及未知自定义文件。
- 回退只替换程序目录，恢复旧版完整文件集；保留升级后新增/编辑的 BD 和设置，不能用旧用户快照覆盖它们。
- 非 ZIP 输入、越界和用户目录载荷在预备前失败，已安装程序和用户文件保持原状。

实际更新器仍 pending：自动检查、下载与可信校验、进程退出协调、失败恢复、重试/重复升级和清理策略均未实现。测试内重命名是顺序模型，不保证断电原子性，不验证 Windows 文件锁、占用、权限或跨盘行为；也不是生产 ZIP 安全校验器。

Windows 验收仍 pending（依赖 R01）：用两份真实候选包，记录版本/提交/哈希；保存含中文名称的真实 BD 和设置，退出后更新，打开核对并修改保存；回退后再次打开核对，确认升级后保存内容保留。还需确认新旧版本数据格式兼容及迁移策略；字节保留不证明旧版可解析新版数据。真实校验失败、占用与更新中断需单独实测。当前无候选包，不请求用户实机操作。
