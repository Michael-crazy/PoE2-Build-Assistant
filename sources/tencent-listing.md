# M02 腾讯市场离线归一化检查点

本轮只读本地文件，复用 M01 的 `scripts/trade_listing.py`，不新增网络组件、不改 PoB。没有研究未文档化端点，也没有登录、抓取或发送实网交易请求。这里定义的是助手的本地输入契约，**不是已验证的腾讯响应格式或访问能力**。

## 契约与复用

```sh
python3 -B scripts/trade_listing.py tests/fixtures/m02/listings.synthetic.json --realm tencent --league '合成腾讯测试赛季'
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
```

沿用 M01 的 `result[]`、`id`、`item`、`listing.price` 输入边界和整批失败语义，详见 [M01 说明](international-listing.md)。函数新增 `realm` 关键字（默认 `international`），CLI 新增 `--realm international|tencent`；原调用保持兼容。输出仍为 `id/realm/league/item/price`。

`realm` 是调用方对输入来源的声明；程序不能据此验证文件来自腾讯，也不根据简体文字猜测服务器。后续合并、缓存或比较数据必须使用 `(realm, league, id)`，不能只用挂单 ID。不同服务器和赛季的价格不可混算。

完整 item 深复制保留，简体名称、基底、稀有度及所有词缀原样输出；价格保留数量、通货文字/标识和报价类型，不翻译、不推断 ID、不换算。缺价格输出 null，空结果输出空数组；赛季不匹配、重复 ID、响应错误、结构损坏和非法价格整批失败，CLI 退出 1，无部分输出。中文稀有度仅作为非空文本保留，**尚不能直接导入 PoB**。

M01 已完成固定 PoB 源码复用评审，本轮直接复用仓库中的 Python 实现，不重复复制或获取上游代码。真实腾讯数据若不同，应在取得合规样本后增加显式转换边界，不能用本地夹具宣称兼容。

## 合成样本

`tests/fixtures/m02/listings.synthetic.json` 顶部 `_provenance` 明示完全自编；两条记录的 ID、赛季、名称和报价也带合成标记。一件传奇、一件四词缀稀有，只用于验证 Unicode 和数据保真；数值、术语和报价类型均无真实性承诺。无真实账号、token、私聊或用户数据。CLI 只输出归一化挂单，文件级 `_provenance` 不进入输出；示例结果仍按合成数据使用。
